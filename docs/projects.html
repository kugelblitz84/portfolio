Professional / ClientAI · Realtime · Deployment

AI Language Tutor / Voice AI Platform

A realtime AI voice tutor where I helped move the project from an expensive prototype to a more practical Pipecat + LiveKit architecture, then implemented the Flutter app flow from Figma.

Context

The prototype used GPT Realtime API, which was not compatible with the cost margin at roughly $40 per 1,000 minutes. The project needed a cheaper architecture while keeping realtime voice interaction feasible.

My role

Researched alternatives, migrated the architecture, solved WebRTC deployment limitations, stabilized async backend operations, deployed on Railway, and implemented the Flutter frontend after prototype validation.

Key contributions

  • Migrated the voice architecture from GPT Realtime API to a Pipecat + LiveKit based solution.
  • Reduced estimated realtime voice cost from about $40 to $14 per 1,000 minutes by limiting paid usage mainly to STT/TTS services.
  • Implemented FastAPI session orchestration with LiveKit token generation, session start/end flow, and bot worker lifecycle handling.
  • Solved LAN-only WebRTC/STUN deployment limitations by moving to LiveKit-supported realtime transport.
  • Split unstable async service flow into separate session/token and bot-worker services to improve Railway deployment stability.
  • Connected the Flutter app flow with realtime session handling and implemented UI from Figma.
Skills shown:FlutterGetXFastAPIPipecatLiveKitWebRTCRailwayGitHub CI/CDSTT/TTSAsync debugging

Professional / ClientResearch · API strategy · Flutter UI

Live Sports Score Platform

A FotMob-style football score platform where I researched sports data providers, selected a cost-effective API strategy, coordinated backend planning, and implemented the Flutter UI.

Context

Enterprise providers like Opta/StatsPerform were too costly for the client. The project needed a cheaper sports data provider while still supporting fixtures, live scores, standings, teams, players, and match details.

My role

Researched available providers, selected API-Football based on cost and feature coverage, documented endpoint mapping, identified composite features, and worked with the backend team on implementation planning.

Key contributions

  • Selected API-Football as a budget-fit alternative after researching sports data provider options.
  • Documented endpoint mapping for fixtures, live scores, standings, teams, players, coaches, match details, and related flows.
  • Identified composite features requiring multiple API responses and explained backend-side aggregation strategy.
  • Worked directly with backend developers to plan API usage, limitations, response structure, and feature feasibility.
  • Implemented the Flutter frontend UI for a FotMob-style sports experience.
